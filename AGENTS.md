# AGENTS.md

b4agent: a coding harness built as extensions on a pinned Pi (`@earendil-works/pi-coding-agent` 1.4.0). The design lives in `../docs/harness-plan.md`.

## Checks

- `npm run typecheck`
- `npm test` (vitest)
- `npm run build` before using `dist/src/cli.js` (the `b4agent` command)

## Layout

- `src/permissions/`: the permission gate (plan section 1).
  - `shell/`: bash parsing with unbash, word flattening, wrapper unwrapping, command extraction.
  - `rules/`: verdicts for bash and for Pi's built-in tools. `fallback.ts` holds the regex hard-denies used when parsing fails.
  - `paths.ts`: critical, protected, credential and own-guard paths.
  - `git.ts`: repository root, branch, and which deletes checkpoints can't restore (gitignored, large untracked).
  - `gate.ts`: mode routing (auto / manual / yolo) and session grants. `config.ts`, `log.ts`: config and the JSONL audit log.
  - `review/`: the auto-mode reviewer. `input.ts` builds what it sees (user messages, action, gate facts; never assistant text or tool output), `jev.ts` holds the Jev questions and thresholds, `llm.ts` the LLM prompt with a forced tool, `reviewer.ts` the Jev, then LLM, then user fallback.
- `src/checkpoints/`: file checkpoints (plan section 17). `store.ts` is the shadow git repo per worktree (`write-tree` snapshots, own index, per-path restore; never run `git gc` on it, the trees have no refs). `plan.ts` works out from session entries which files a rewind restores.
- `src/agents/`: subagents (plan sections 2 and 11). `hub.ts` owns the roster, child sessions, delivery, waits and worktree patches; `tools.ts` holds `agent`, `message`, `agents` and the child tools; `types.ts` loads `agents/*.md`; `worktree.ts` is opt-in isolation; `stale.ts` is the stale-read guard; `panel.ts` is the panel and the transcript overlay.
- `src/jobs/bash.ts`: bash with background jobs and Ctrl+B.
- `src/schedule/`: `scheduler.ts` is the pure scheduler behind `/loop` and the schedule tools; `durable.ts` is `projects/<key>/schedules.json` (lock file for writes, O_EXCL claim per job and generation when a session picks a job up, holder pid/session); `pacer.ts` is the self-paced `/loop` and its fallback wakeup; `settings.ts` reads `schedule.fallbackWakeupMinutes`. `tests/schedule/`, `tests/e2e/schedule.sh` (durable schedules across a restart with two sessions opening at once, and the fallback).
- `src/config.ts`: `~/.b4agent/b4agent.json` (model roles, per-type overrides, jobs, depth). `src/prompt.ts`: the b4agent preamble and Pi's rebuilt tools and rules sections. `src/keys.ts`: Tab routing. `src/cli.ts`: the `b4agent` command.
- `agents/*.md`: builtin subagent types (frontmatter configures them; the body is the system prompt). `prompt/`: the identity text and the `/review` and `/security-review` briefs.
- `src/extension/index.ts`: `makeExtension({ child? })` loads all of b4agent's extensions together (they share in-process state); children load the same factory in child mode. Use the file with `-e`.
- `src/extension/agents.ts`, `spec.ts`, `schedule.ts`, `commands.ts`: subagent wiring and the panel, spec mode and `exit_spec`, `/loop` and the schedule tools, `/review`. `src/tools/ask-user.ts`: `ask_user`.
- `src/btw/side-chat.ts`, `src/extension/btw.ts`: `/btw`, the side chat. It sends the main agent's next request (captured from `context_with_system` plus the messages since) with the question appended, so the prompt cache is reused; only read-only calls run, through the gate's rules. Saved with `appendEntry`, never `sendMessage`. `tests/btw/` compares its requests with the main agent's through a faux provider; `tests/e2e/btw.sh` drives the overlay.
- `src/tui/steps.ts`, `src/tui/collapse.ts`, `src/extension/steps.ts`: collapsed agent steps (plan section 25). `steps.ts` counts and groups (shared with the subagent overlay); `collapse.ts` patches Pi 1.3.0's tool and assistant components at runtime, so re-check it on a Pi upgrade. Ctrl+O cycles grouped, every step, full output. Running calls stay folded (no flash); every tool has a phrase in `KIND` in `steps.ts`, and unknown tools are named. `src/tui/rainbow.ts`: rainbow prompt border and footer effort at the model's top reasoning level (wraps `Theme.prototype.getThinkingBorderColor`; re-check on a Pi upgrade). `src/tui/reference.ts`: highlight-to-reference (fullscreen only; reads pi-tui's private `getActiveSelectionText`).
- `skills/`: bundled skills, added to every session through `resources_discover` in `src/extension/index.ts`. Each vendored skill has an `UPSTREAM.md` and its upstream LICENSE; `vendor.json` is the manifest and `node scripts/vendor-diff.mjs <name>` shows upstream changes since the pin. Credits are in `NOTICE`.
  - `skills/{docx,xlsx,pdf,pptx}/`: office skills with Python CLIs and pytest suites (`python -m pytest skills/<s>/tests`); `scripts/check_deps.py` is the same file in each. `skills/office-read/` routes plain reading.
  - `skills/create-verification-skill/`, `skills/maintain-verification-skill/`: pstack's verification pair, user-invoked only (`disable-model-invocation`). The first writes a project's `verify-<app>` skill (launch, doctor, drive, evidence, cleanup, feature map) that agents load after changes; the second keeps it honest.
  - `skills/create-subagent/scripts/check_agent.mjs` imports `dist/src/agents/types.js` and `dist/src/config.js`: build first, and re-check it when `parseAgentType` or the config shape changes.
- `src/context/nested.ts`, `src/context/rules.ts`, `src/extension/nested.ts`: subdirectory AGENTS.md and path-scoped rules on demand (plan section 19), appended to tool results as `<nested-instructions>`, with a ledger read from the branch's compaction-aware context. `tests/context/`; `tests/e2e/context.sh` covers this and memory. The other e2e scripts launch with `-nc`, which turns nested loading off.
- `src/memory/store.ts`, `src/extension/memory.ts`: auto memory (plan section 26). Global `~/.b4agent/memory/` and project `projects/<key>/memory/`; the `MEMORY.md` indexes go in a `memory` section snapshotted at session start or compaction (keep it byte-stable), read-only for subagents (write/edit and bash writes); `/memory`. `tests/memory/`.
- `src/web/`, `src/extension/web.ts`, `src/permissions/rules/web.ts`: `web_fetch` and `web_search` (plan sections 18 and 8). `ssrf.ts` checks addresses inside the connection's DNS lookup; `http.ts` is one GET with the cap after decompression; `fetch.ts` handles redirects, markdown-first, Cloudflare, rate limits and the cache; `convert.ts` charset, Readability + Turndown, unpdf; `format.ts` the untrusted fence and paging; `prompt.ts` the smol prompt mode; `search.ts` hosted search over `openai-codex`/`openai`; `provenance.ts` which URLs count as seen. `web_search` is registered only when an OpenAI login exists. `B4AGENT_TEST_WEB_ALLOW_LOOPBACK=1` is a test hook (loopback only). `tests/web/`, `tests/e2e/web.sh`.
- `src/recap/`, `src/extension/recap.ts`: thread recap (plan section 3). `trigger.ts` conditions, conversation leaf and settings; `controller.ts` the away timer, cancel, leaf check and resume; `generate.ts` the main-model path (the /btw `ask()` with the recap request appended) and the small-model path; `widget.ts` the dim `✦ recap` lines. `B4AGENT_RECAP_LOG=<file>` logs routes and skips. `tests/recap/`, `tests/e2e/recap.sh`.
- `themes/`: the 19 bundled themes, passed to Pi with `--theme` by `src/cli.ts` (Pi applies the saved theme before extensions register theirs). `src/tui/theme.ts`: pack order and the `/theme` picker.
- `src/extension/tui.ts` with `src/tui/{header,footer,cold-cache,spinner,notify,changes,settings}.ts`: header, 3-line footer (chips from every `setStatus`, the cold-cache hint), Pac-Man spinner, title and bell, `/changes`. `src/tui/focus.ts` is the process-wide DEC 1004 focus tracker (`onAwayChange`); it uses a raw stdin listener because Pi's fullscreen viewport consumes focus reports. `src/extension/autotitle.ts`, `diagnostics.ts`, `environment.ts`: session title from a small model, checker diagnostics after edits, the `environment` prompt section. `tests/tui/`, `tests/e2e/tui.sh` (with the test-only `tests/tui/probe.ts`).
- `src/painter/`, `src/extension/painter.ts`: the `painter` tool (plan section 8): Codex CLI's images request, backend order Codex login, OpenAI key, OpenRouter; saves to `~/.b4agent/projects/<repo>/images`. Registered on session start only when a backend has credentials. `src/extension/init.ts` + `prompt/init.md`: `/init`. `src/extension/usage.ts`: `/usage` (plan limits from `wham/usage`, falling back to the last `x-codex-*` headers, plus session totals). `tests/painter/`, `tests/usage/`, `tests/e2e/misc.sh` (a local stub of chatgpt.com).
- tuistory `snapshot` can include one scrollback line above the screen once it has scrolled; count rows up from the footer when sending mouse coordinates (see `tests/e2e/steps.sh`).
- `src/agents/schema.ts`: output schemas (checks, validation, submit reminders, forcing the submit tool per provider). `src/agents/create.ts`: `agent_create` (dialog, write, hot reload). `tests/agents/structured.test.ts` runs both through a real Pi session with a fake model; `tests/e2e/agents2.sh` covers the dialog, schema retry, reminders and the section update. The e2e scripts accept `B4_TUI_SESSION` for the tuistory session name (`agents.sh`, `agents2.sh`).
- `src/history/`, `src/extension/history.ts`, `agents/historian.md`: `session_search` and `session_read` (plan section 2). `sessions.ts` streams Pi's session JSONL newest first and stops once the page is full; `transcript.ts` the numbered transcript with branch markers, paging and the untrusted fence; `digest.ts` the smol `question` mode; `redact.ts` secret removal before any cut; `paths.ts` Pi's session-folder naming. Active in main; in children only when a type's `tools:` names them. Never open a session with `SessionManager.open` (it can rewrite the file). `tests/history/`.
- `src/hooks/`, `src/extension/hooks.ts`: settings-defined shell hooks in Claude Code's format (plan section 28). `config.ts` loads, matches and evaluates `if`; `run.ts` spawns hooks and reads exit codes and JSON; `decide.ts` combines results per event. Registered before every `tool_call` guard and the gate; `src/permissions/hooks.ts` carries a hook's allow or ask to the gate. `/hooks`. `tests/hooks/`, `tests/e2e/hooks.sh` (print mode; needs `npm run build`).
- Any e2e script that launches `dist/src/cli.js` must write an empty `auth.json` into its temp agent dir first: the launcher copies `~/.pi/agent/auth.json` into an empty agent dir on first run.
- `src/extension/permissions.ts`: the Pi extension (`tool_call` handler, dialog, `/permissions`, `--yolo`, `--permissions`).
- `src/extension/checkpoints.ts`: captures on every user message and run end, `/rewind`, and code restore offered on Pi's `/tree` and `/fork`.
- `tests/permissions/`: command-to-verdict tables. Add a row for every rule change, with an input where a plausible wrong implementation gives a different answer.
- `tests/e2e/scripted-model.ts`: a scripted model for end-to-end runs (`B4_SCRIPT` maps prompts to tool calls), used with tuistory or print mode.
- `tests/e2e/checkpoints.sh`: the checkpoint scenario in a real terminal (rewind, conflicts, undo, `/tree` both ways). Run it after changing `src/checkpoints/` or `src/extension/checkpoints.ts`.
- `tests/e2e/agents.sh`: subagents, the panel and transcript, delivery, background bash, Ctrl+B, the stale-read guard, and a child's permission dialog. `tests/e2e/modes.sh`: spec mode, `ask_user`, Tab routing, Alt+M (permission mode), schedules, `/review`. `tests/e2e/steps.sh`: collapsed steps (grouped, expanded, click on one group, an error in a group, live progress, the subagent overlay) and highlight-to-reference. The e2e scripts run in fullscreen, Pi's default `tuiMode`. Run them after changing the matching code. Set `PI_CODING_AGENT_DIR` to a temp dir in any new script, or real logins get used.
- `eval/reviewer/`: labeled cases for the reviewer. `npm run eval:reviewer` makes live Jev and LLM calls and searches thresholds; `SET=holdout` checks the held-out set. Re-run it when the Jev version, the questions or the LLM prompt change, and never tune on the holdout.

## Rules

- Hard denies live in code, never in config.
- Use `.js` suffixes on relative imports (NodeNext).
- Don't patch `node_modules`; work around Pi through its extension API.
