## Junk patterns

Reject new matches unless the [retention bar](#retention-bar) identifies an independent contract. Audit existing matches:

- Assertion-free probes, self-comparisons, identity copiers, expected values generated by the subject.
- Copied inventories, manifests and export lists; exact source, import or string greps.
- Private predicate or call-shape tests duplicating boundary proof; repeated invocations or per-provider replays of shared helpers.
- Test-only exports, globals and wrappers; production paths called only by tests.
- Mocks implementing the asserted behavior, or pretending distinct APIs match.
- Fixtures supplying receipts, admission or callback ordering that the owner should produce; persistence asserted against a store path the code never writes.
- Capability flags asserted instead of the promised delivery or acknowledgement.
- Negative controls passing on an unrelated guard or an unreachable rejection.
- Names promising behavior that the inputs and assertions never exercise.

## Retention bar

- Keep independent public API, SDK, protocol, config, migration, storage, security, platform, default, prompt-byte, generated cross-language, package, release and architecture contracts. Keep observable ordering and credible regressions.
- Source inspection is valid when it is the cheapest independent guard of a user-facing key, byte or path, and survives identifier-only refactoring.
- Static or slow is not a reason to delete. A baseline failure may be a product bug: reproduce it and repair the owner; never delete the test for it.

## Candidate evidence

- Before editing, read the full test, its production owner, entry point, callers, callees, siblings, overlapping proof, CI wiring and history. For claims that depend on a dependency, inspect the dependency's source or types. Read the root and scoped `AGENTS.md`.
- Record for each candidate:
  - exact name and location, and the failure it detects;
  - non-test callers of the production or support seam it covers;
  - the stronger proof that remains at the owner, or why none is needed;
  - why it exists (history), and what its deletion unlocks;
  - risk, and the focused command that validates the change.
- Missing evidence means no deletion. Discovery is read-only; report before editing. Prefer a few high-confidence candidates. Parallel discovery (subagents) may split independent owners.
- Delete obsolete seams and dead paths; move retained regressions to the owner; consolidate generic package or dependency contracts.
- Prefer a net reduction in production code. Never add replacement implementation tests or turn uncertainty into cleanup.

## Validation and handoff

- Don't edit the checkout during an active test run. Run the owner and sibling tests.
- Where you removed source greps or plan assertions, exercise the owning executable or its dry run instead.
- Run the project's format and lint checks on the changed files, and `git diff --check`.
- After removing tests, look for support files, fixtures, helpers and exports that only they used, and remove those too; use the project's dead-code or unused-export check if it has one.
- Inspect `git diff --numstat`; get a final review of the diff.
- Report causes, removed categories and seams, retained false positives, proof and cost, production versus test and support lines, PR state, follow-ups.
- Commit, push or land only when authorized. Refresh from the main branch and rediscover before another audit batch.
