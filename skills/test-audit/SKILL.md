# Test Audit

- The authoring gate below is the bar every test you keep or rewrite must meet.
- Audits remove low-value proof in coherent batches, one production owner at a time; never chase deletion counts.
- Pruning a whole subsystem's tests: read [CAMPAIGN.md](CAMPAIGN.md) first.

## Authoring gate

Before adding a test, answer:

1. What observable behavior, invariant, or independent contract does it protect?
2. What credible regression would make it fail?
3. Why does existing proof miss it? Each contract gets one primary owner at the strongest boundary. Another layer needs a distinct transport or lifecycle risk. Extend existing tables and shared fixtures; consolidate repeated setup.
4. Does it need an export, flag, wrapper or injection hook that no production caller needs? Move the proof to the real boundary instead.

- Prove behavior at the owning boundary: read the [boundary and cost guide](references/writing-tests.md).
- A regression test must fail before the fix for the intended reason and pass after the repair. Say so when you couldn't show the failing baseline.
- One regression at the owner covers a bug; never replay it at every layer it crosses.
- A behavior-preserving refactor should not break the test.

## Junk patterns

- Reject self-comparisons, copied inventories, source greps, implementation and call-shape assertions, duplicate contracts, test-only seams, expected values generated by the subject, and mocks that supply the asserted behavior.
- Fixtures must not fabricate the owner's receipts or ordering, or claim a persistence path the code never writes.
- Negative controls must fail at the intended guard; test names must match the behavior exercised.
- When auditing candidates, use the [full checklist](references/audit.md#junk-patterns).

## Retention bar

- Keep independent API, SDK, protocol, config, migration, storage, security, platform, default, prompt-byte, generated-language, package, release, architecture and observable-ordering contracts. Static or slow is not disposable.
- Source inspection must survive identifier-only refactors and guard an independent user-facing contract.
- A baseline failure may be a bug to repair, not a test to delete.

## Audit and validation

- Before an audit edit, read [candidate evidence and workflow](references/audit.md#candidate-evidence); inspect the full owners, callers and history, and record the remaining proof before deleting anything.
- Delete obsolete production seams together with their tests; never optimize for deletion counts.
- Prove narrowly: run the touched tests and their owner and sibling suites, plus the project's typecheck, lint and format checks for the changed files. Follow the project's `AGENTS.md` for its commands. Don't edit files while a test watcher or test run is using the checkout.
- For a large or risky batch, get a review of the diff (the `reviewer` subagent, or `/review`).
- Report causes, retained contracts, proof and its cost, production versus test lines changed, and follow-ups. Commit, push or merge only when the task authorizes it.
